# GROT — приложение для бара и ресторана

Платформа для реального заведения в Паттайе: заказы гостей, обслуживание зала,
экран кухни, доставка, склад, CRM и аналитика — одна кодовая база, шесть ролей,
один API.

**~5 000 строк прикладного кода на 5 рантайм-зависимостях.** Авторизация,
хеширование паролей, защита от перебора, персистентность и драйвер чекового
принтера написаны руками, а не подключены пакетами.

🔗 **Демо:** https://grot-app.onrender.com · 🇬🇧 [English version](README.md)

> Зарегистрируйтесь с любым номером, чтобы посмотреть гостевую часть целиком.
> Панели персонала и управления закрыты паролем — демо-аккаунты намеренно не
> создаются в продакшене, причина в разделе [Безопасность](#безопасность).

## Что умеет

Шесть ролей работают через один API, у каждой своя навигация и свои права.

| Роль | Возможности |
|---|---|
| **Гость** | Меню, корзина, доставка и самовывоз, бронь стола, вход за стол по QR, чат с курьером, события, уровни лояльности |
| **Официант** | Открытые счета по столам, добавление позиций в текущий заказ, разделение счёта, закрытие наличными или картой, вызовы от гостей |
| **Кухня** | Живая очередь тикетов, стоп-лист по позициям, отчёт за смену |
| **Курьер** | Назначенные доставки, маршрут до адреса, чат с гостем, подтверждение выдачи |
| **Администратор** | Заказы, брони, наличие позиций, персонал, push-рассылки |
| **Владелец** | Аналитика выручки и среднего чека, статистика по сотрудникам с выгрузкой в CSV, CRM, склад, управление персоналом |

Помимо очевидного CRUD:

- **Склад по технологическим картам.** У каждого блюда описаны ингредиенты;
  закрытие заказа списывает остатки автоматически и подсвечивает позиции ниже
  минимума.
- **Печать на Bluetooth-принтер.** Кухонные тикеты и чеки печатаются на ESC/POS
  прямо из Android-сборки.
- **Двуязычность как продуктовое решение.** Гостям — английский, потому что
  Паттайя туристическая; персоналу и управлению — русский. Это не недоделка:
  перевод применяется по роли в `App.jsx`.
- **Устанавливается.** PWA с сервис-воркером плюс нативные сборки под iOS и
  Android через Capacitor из того же исходника.

## Стек

**Backend** — Node.js, Express, ES-модули. Из рантайм-зависимостей только
`express` и `cors`. 64 REST-эндпоинта.

**Frontend** — React, Vite, React Router. Без UI-китов, без стейт-менеджера, без
CSS-фреймворка — своя вёрстка на дизайн-токенах, состояние через Context.

**Мобильные** — Capacitor (iOS + Android), сервис-воркер, Web Push.

**Инфраструктура** — Docker, Render Blueprint (`render.yaml`), постоянный диск.

## Архитектура

```
backend/
  server.js        64 REST-эндпоинта, валидация, бизнес-правила
  db.js            доменное состояние в памяти + сиды для разработки
  persistence.js   снапшот в JSON, атомарная запись + ротация бэкапов
  security.js      токены, хеширование паролей, rate limit, ролевой доступ
  integrations/    карты, web push, SMS
frontend/src/
  screens/         по файлу на экран каждой роли
  components/      общие UI-примитивы
  context/         глобальный стор — авторизация, корзина, язык, тосты
  i18n.js          словари RU/EN
  printer.js       ESC/POS по Bluetooth
```

**Хранение.** Состояние живёт в памяти и снапшотится в JSON на диск, поэтому
переживает рестарты и деплои. `persistence.js` намеренно единственный модуль,
который знает о хранилище: переход на PostgreSQL — это замена одного файла без
правок слоя API. Для одного заведения такой размен масштабируемости на нулевую
эксплуатацию был правильным.

**Цены заказа.** Клиент присылает только id позиций и количество. Сервер берёт
своё меню, пересчитывает сумму и отклоняет недоступные блюда или еду, заказанную
при закрытой кухне. Ценам с клиента доверия нет.

## Безопасность

Написана без auth-библиотек, поэтому каждое решение явное:

- **Токены** — подпись HMAC-SHA256, проверка через `crypto.timingSafeEqual`,
  чтобы сравнение не утекало по таймингу.
- **Пароли** — scrypt со случайной солью на пользователя, сравнение за
  постоянное время.
- **Перебор** — rate limit со скользящим окном на эндпоинтах авторизации,
  10 запросов в минуту на IP и путь.
- **Авторизация** — `requireRole()` на каждом эндпоинте персонала; роль берётся
  из проверенного токена, а не из тела запроса.
- **Mass assignment** — белый список полей через `pick()` с явной защитой от
  `__proto__` и загрязнения прототипа.
- **Демо-аккаунты** — создаются только в разработке. Репозиторий публичный, и
  создание их в продакшене отдало бы любому желающему аккаунт владельца. Первый
  владелец в проде заводится из `OWNER_PHONE` / `OWNER_PASSWORD`, а сервер при
  старте предупреждает о любой учётке с демо-паролем.
- **Секрет подписи** — из переменных окружения либо генерируется один раз и
  лежит с правами `0600` на постоянном диске.

## Запуск локально

Нужен Node.js 18+.

```bash
git clone https://github.com/artemfazleev1-cmd/grot-app.git
```

```bash
cd grot-app && npm run install:all
```

Backend на `:4000`:

```bash
npm run dev:backend
```

Frontend на `:5173`, проксирует `/api` на backend:

```bash
npm run dev:frontend
```

Открыть http://localhost:5173. В разработке разворачивается полное заведение —
38 позиций меню, 41 ингредиент, 16 столов, тестовые заказы — и такие аккаунты:

| Роль | Телефон | Пароль |
|---|---|---|
| Владелец | `+66800000000` | `owner` |
| Администратор | `+66811111111` | `admin` |
| Официант | `+66822222222` | `waiter` |
| Кухня | `+66833333333` | `cook` |
| Курьер | `+66844444444` | `courier` |
| Гость | `+66855555555` | `client` |

## Деплой

`render.yaml` — это Render Blueprint: указываете Render на репозиторий, он
собирает Docker-образ, монтирует диск на 1 ГБ под состояние и генерирует секрет
подписи. Задайте `OWNER_PHONE` и `OWNER_PASSWORD`, чтобы создать первого
владельца. Web Push, SMS и карты включаются при наличии ключей и тихо
отключаются без них.

Мобильные сборки через Capacitor:

```bash
npm run build:app
```

## Что бы я сделал иначе

- **TypeScript с самого начала.** Заказы, роли и статусы — ровно те формы, ради
  которых типы и нужны. Перевод в планах.
- **Тесты.** Их нет. Честная причина — проект делался в срок для заведения,
  которому он был нужен работающим. Важнее всего `security.js` и
  `persistence.js`, с них и начал бы.
- **PostgreSQL.** JSON-снапшот верен для одного заведения и неверен для двух.
  Абстракция готова, миграция — нет.
- **Разбить `server.js`.** На 861 строке это должны быть роутеры по доменам.
- **Оптимистичный UI на экране официанта.** Сейчас каждое действие идёт на
  сервер, и на заведенческом Wi-Fi это заметно.
